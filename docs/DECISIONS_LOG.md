| 3 | Roger Roger color scheme (blue `#428EF4` CTAs, clean white) | Modern, minimal aesthetic. Blue conveys trust and professionalism for business users. | 2026-05-01 |

| 5 | Retell AI + Twilio for voice (not building voice AI from scratch) | Months of audio engineering saved. Retell handles STT/TTS/turn-taking, Twilio handles telephony. We focus on the AI brain and UX. | 2026-05-01 |
| 6 | Claude Sonnet 4.6 as AI brain (not GPT) | Strict tool use mode guarantees valid parameters. Critical for booking appointments and generating quotes mid-call without hallucinated fields. | 2026-05-01 |
| 7 | Mobile-first design | Users (business owners) primarily check their receptionist from their phone. Desktop is secondary. | 2026-05-01 |
| 8 | Feature isolation pattern | Same modular architecture as Lemlin. Features cannot import other features (ESLint enforced). Prevents cascading breakage when one feature changes. | 2026-05-01 |
| 9 | Reuse marketplace10's Unipile credentials and pattern | Unipile account already connected and paid for hub.nfstay.com. Same token/DSN works for Poppy — no extra cost. | 10 | String equality webhook auth (not HMAC) | Unipile only supports `Unipile-Auth` header with a shared secret string. No HMAC signing available. Acceptable for now; the secret is stored in Vercel env vars, not in code. | 2026-05-02 |
| 11 | ~~gpt-4o-mini~~ → Claude Sonnet 4.6 for WhatsApp auto-replies | Switched to Claude for consistency across the stack. One AI provider, one prompting style, one billing line. Claude Sonnet is fast enough for chat replies and better at following the business system prompt. | 2026-05-03 |
| 12 | Download attachments to Supabase Storage (not hotlink Unipile URLs) | Unipile attachment URLs are temporary/authenticated. Storing in our own Storage bucket gives permanent public URLs and no vendor lock-in for media display. | 2026-05-03 |
| 13 | Regex filter for reaction notification texts (not just `is_event` flag) | Unipile sends reaction notifications with `is_event=0` sometimes. Belt-and-braces: filter by both the `is_event` flag AND by detecting the text pattern `"{{phone@s.whatsapp.net}} reacted X"`. | 2026-05-03 |
| 14 | Vercel CLI deploy with `.git` hide trick | Vercel project is linked to `hrds100/poppy` repo but code lives in `limdin25/poppy`. Auto-deploy doesn't trigger. Workaround: `mv .git .git.bak && vercel deploy --prod && mv .git.bak .git`. Works reliably. | 2026-05-03 |
| 15 | Video as first-class content type | Added `'video'` to the messages content_type constraint alongside text/audio/image/file. Frontend renders `<video controls>` with the media_url. Future-proofs for WhatsApp video messages. | 2026-05-03 |
| 16 | AI draft replies in poll.ts (not just webhook) | Unipile webhooks are unreliable — many WhatsApp messages arrive only via polling. Poll.ts now generates AI draft replies for new inbound messages, same as the webhook path. Belt-and-braces. | 2026-05-03 |
| 17 | Draft rewrite + inline edit (not just approve/discard) | Users need control over AI drafts before sending. Added rewrite (regenerate via Claude) and edit (inline textarea) buttons alongside discard/approve. Works for all channels. | 2026-05-03 |
| 18 | Reuse existing Retell agent + SIP trunk (not rebuild from scratch) | Hugo already had Retell agent, LLM, SIP trunk, and imported phone number configured. Updated the LLM prompt to Elsie's format and pointed webhook to our endpoint instead of n8n. | 2026-05-03 |
| 19 | Two-step Retell setup: LLM then Agent | Retell API requires creating an LLM object first (holds the system prompt), then an Agent referencing the llm_id. The agent itself has no prompt field. | 2026-05-03 |
| 20 | Claude Sonnet for call transcript extraction (not OpenAI) | Consistent with our AI stack — one provider, one billing line. Claude extracts caller name, phone, reason, summary, action_required from transcripts. | 2026-05-03 |
| 21 | Web Crypto API for webhook verification (not Node.js crypto) | Vercel edge runtime doesn't support Node.js `require('crypto')`. Retell signature format is `v=timestamp,d=hmac_hex` using HMAC-SHA256 with the API key as secret. | 2026-05-03 |
| 22 | No long dashes, anywhere, ever | Hugo's standing rule, 2026-07-27. Applies to code, comments, docs, UI copy, customer messages, AI prompts and replies to him. It is not only taste: a text is GSM-7 (160 characters a segment) only if every character is in the GSM 03.38 table, and one em dash flips the whole message to UCS-2 at 70 characters a segment. The old video text was 164 characters and cost 3 texts; the rewritten one is 211 characters, longer and warmer, and costs 2. Enforced by `tests/message-copy.test.ts`, which fails the build. Helpers in `api/lib/sms-charset.ts`. Curly quotes and the ellipsis character do the same damage and are banned with it. | 2026-07-27 |
| 23 | Video send text invites a reply, and says when there is no website | Hugo, 2026-07-27: "if you have any question please just shoot me a message at any time" and "you say you don't have a website when they don't have". Both variants now close with "Any questions, just message me here any time", laid out in paragraphs with the link on its own line so it is tappable on a phone. Both variants send the SAME message, because the audit runs from Google either way; the earlier no-website wording claimed it ran "from your Google listing instead", which read as a difference where there is none. The no-website variant only ADDS a P.S. | 2026-07-27 |
| 24 | Free-website offer REINSTATED, no-website variant only | Hugo, 2026-07-27, reversing his own withdrawal of 2026-07-26: "I couldn't find website. If you don't have one, you can make one for free, just let us know." It rides only `send_template_no_site`, as a P.S. after the identical message everyone else gets, so a lead who already has a site is never told we could not find one nor offered a second. Costs a third SMS segment (339 characters vs 211); Hugo asked for it knowing the message gets longer. `tests/message-copy.test.ts` and `tests/vsl-funnel.test.ts` previously asserted the offer stayed withdrawn and now assert the opposite, with the full history in the comments so nobody "fixes" it back. | 2026-07-27 |
| 27 | Builder roster is its own admin-only table, matched to a house by plain postcode outcode (not geodistance) | Hugo, 2026-08-14: sourcing houses nationwide means one builder near Pedro can't be the viewer for every house, so a roster of local builders is matched by postcode when a viewing is booked. `brrr_builders` follows the exact `brrr_properties` pattern: no RLS, service-role only via `api/admin/builders`. Matching reuses the existing `outcodeOf()` from `api/lib/brrr-deal-facts.ts` rather than a new geocoding dependency: exact outcode match first (e.g. `LE7`), falling back to the bare area prefix (`LE`) only when nobody covers the exact outcode. No match returns nothing, never a guessed "nearest" builder. See [BRRR_STRATEGY.md §9a](../../scraper/BRRR_STRATEGY.md). | 2026-08-14 |
| 28 | `npx tsc --noEmit` at the repo root silently checks nothing | Discovered 2026-08-14 shipping the builder roster: `tsc -b` (what `npm run build` actually runs) caught a real type error — `useAdminMutation`'s method union was missing `'DELETE'` — that `npx tsc --noEmit` had reported zero errors on moments earlier. The root `tsconfig.json` is solution-style (`"files": []`, only `references`), which plain `tsc --noEmit` does not build, so it type-checks nothing and exits clean regardless of real errors. The documented test-loop command (`npx tsc --noEmit && npx vitest run`) needs `tsc -b` in place of `tsc --noEmit` to mean anything; until that's changed, verify with `npx tsc -b`. | 2026-08-14 |
| 25 | The offer strip above Pedro's script FOLDS, and starts folded | Hugo, 2026-08-14: "please give option to colapse all this and start colapsed so pedro can read the script property." The strip had grown to six rows (next step, address, strategy and band, three money cells, evidence, reason) and was pushing the script off the fold, which is the opposite of why it was pinned there. Collapsed it is one line: address, asking price, which of the two calls this is. No figure of ours is on screen until he opens it. `startCollapsed` is passed by the dialer ONLY; Call history leaves it open, because there the deal is the thing being read. | 2026-08-14 |
| 26 | Every property call writes a next-step brief onto the house | Hugo: "build the brain that always after the call gets the exactly instruction for the next step for me to read." A stage tag says where a deal is, not who does what with which number. `api/lib/next-step-brief.ts` writes verdict, asking and opener, why it holds, the instruction, the blockers, the ladder, the board column and a confidence level into `brrr_properties.brief` on EVERY outcome, and the same text is the notification body. Deterministic, no model, same law as `nextStep.ts`. Every figure is read from `offerRange`/`ladderText`/`brrr-deal-facts`, never re-derived. A missing fact becomes a blocker, never an assumption. | 2026-08-14 |
| 27 | Hugo's pinned note is a column of its own, never `notes` | `brrr_properties.notes` holds the scraper's listing description, and nothing on screen ever read it. `pinned_note` is human-written only, survives every re-scrape (the ingest upsert does not carry it), and renders ABOVE the machine's brief because a human decision outranks a generated one. Written from the admin Properties drawer (`save_note`), never by the outcome route. | 2026-08-14 |
| 28 | The 16-question checklist MERGES instead of replacing | The checklist opens blank on every call and the outcome route wrote it straight through, so ringing a branch twice wiped everything the first call learned, including the figure. A blank field now means "not asked this time", not "the answer is nothing". Found while building the brief, whose confidence score is computed from exactly those fields. | 2026-08-14 |
| 29 | The email to the branch is asked for, written and SENT on the call | Hugo: "he asks can I have your email, they give it, and he says I'm sending you an email now, please confirm you received it." Its own tab in the calling room, property calls only. The address types itself from what the coach hears (`api/lib/spoken-email.ts` handles "d dot smith at zest dot co dot uk"); the copy is written from the live transcript; the fixed template is always in the box as the fallback. An email the agent watched arrive gets read, and a mistyped address is caught while they are still on the line instead of when an offer silently never lands. | 2026-08-14 |
| 30 | A refused video must never cost us the email address | The email ask used to hang off the video ask, so a branch that said no to one said no to both. The video is a bonus, the address is the call: it is now its own question with the word "anyway" in it, and there is a second two-line email ("No video, just my address") that asks for NOTHING, because a branch that has just refused one thing will refuse a second ask in the same breath. | 2026-08-14 |
| 31 | Call one's email can never carry a figure, and there are three fences | The prompt forbids it, the writer is never given the numbers at all (`videoFacts` carries no offer, asking, GDV or refurb), and a draft that names one anyway is refused with a 422 so the plain template sends instead. `address_only` sits inside the same guard as `video_request`. A rule a model is told can be broken; a number it was never given cannot be. An email cannot be unsent. | 2026-08-14 |
| 32 | `wk-email-send` accepts a typed recipient (`to_email`) | Sister branches of one agency routinely share a single inbox and `wk_contacts` has a UNIQUE index on email, so storing the address first is not always possible. Refusing to send because another branch already holds that address would be absurd. The address is validated server-side, and written onto the lead AFTER the send, best effort. | 2026-08-14 |
| 33 | `firstText()` is the only way to read an Anthropic response | THE BUG: `claude-sonnet-5` answers with a `thinking` block FIRST, so `content[0].text` is undefined and `callLLM` returned an empty string every single time. Both AI email drafts had failed on production from the day they shipped ("The model did not answer") while the API call itself was perfectly fine. Found by replaying the request by hand against the production key and reading the raw JSON. `api/lib/anthropic-content.ts` is a pure module (so it is testable without a Supabase client) and the other five Anthropic readers in `api/` now use it too: they resolve to sonnet-4-6 and worked, and would have gone silent the day anyone switched `platform_settings.ai_model`. | 2026-08-14 |
| 34 | The transcript table columns are `body` and `ts` | `draft-offer-email` asked for `text, created_at`, which do not exist on `wk_live_transcripts`. PostgREST 400d, the catch swallowed it, and every AI offer email was written as though the call had never happened. A failed read is now logged instead of silently becoming "no transcript". | 2026-08-14 |
| 35 | An unknown coach card kind must never white-screen the coach | `COACH_ICONS[event.kind]` was undefined for any kind this build had not heard of, and the render reads `.colour` off it. The server and the browser deploy separately, so a new kind can arrive at any moment, mid-call. It now falls back to the suggestion styling. | 2026-08-14 |
| 36 | Water is its own question on every property call | Hugo: "very important on the prompts to find out if there is any leaking, any roof problems." It was one word inside "the big four", which is not the same as asking. Now asked separately on every house with two follow-ups that get past "I think it's fine", plus the rule that governs the reaction: a leak is not a reason to walk away, it is the reason the price comes down, so never react and never say what it costs us. Pinned by `tests/property-script-isolation.test.ts` in both the script and the coach's copy. | 2026-08-14 |
| 37 | The EPC ask stays, because the register only answers for one house in ten | Measured on the live VPS on 2026-08-14: `rm_epc_subject` holds 4,160 lookups and 394 matches, 9.5%. The register keys on a house number and listings rarely print one, and it returns the floor area only, not the boiler, insulation or walls. So asking the branch is the fallback for the other 90%, not a duplicate. | 2026-08-14 |
